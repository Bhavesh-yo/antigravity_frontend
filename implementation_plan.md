# Technical Implementation Plan: Dual-Theme MPLADS AI Dashboard

## 1. Executive Summary: The Dashboard Experience

The dashboard will be split into two distinct modes using a toggle switch at the top. This persona-driven design ensures users only see data relevant to their goals.

### Theme A: MP Planner Mode (Smart Fund Utilization)
Designed to help Members of Parliament plan their budgets efficiently.
1. **Sector Gap Analysis:** A visual chart showing how the MP's funds are distributed across sectors (Education, Health, Infra) compared to state averages.
2. **Cost Benchmarking Tool:** A search tool where an MP can input a project type and see the mathematically calculated median cost for that region.
3. **Agency Efficiency Leaderboard:** Ranks Implementing District Authorities (IDAs) based on who completes projects the fastest with the fewest red flags. *(Fix applied: Swapped 'Vendors' to 'IDAs' to match real data).*
4. **Convergence Board (Stalled Projects):** Highlights critical projects that are stalled due to lack of funds, allowing MPs to pool their resources and collaborate.

### Theme B: Oversight Mode (Fraud & Anomaly Detection)
Designed for Ministry officials to audit the scheme.
1. **Constituency Risk Ranking:** Ranks constituencies by their **Anomaly Rate** (`(Total Flagged Projects / Total Projects) * 100`). *(Fix applied: Prevents Division by Zero).*
2. **Agency Risk Ranking:** Ranks IDAs based on their Anomaly Rate.
3. **Sector Vulnerability Index:** Ranks sectors (e.g., Roads vs. Education) to show where fraud or delays occur most frequently.
4. **Fraud Typology Breakdown:** A chart showing the distribution of the *methods* of anomalies (e.g., 50% Cost Overruns, 30% Delays, 20% Duplicates).
5. **AI-Generated Explanations (LLM Integration):** When an official clicks on a flagged project, a side-panel opens displaying a plain-English explanation generated by a Large Language Model (e.g., Gemini/OpenAI). Instead of raw data, the user reads: *"This project was flagged because its description is 95% identical to Project ID 1234 sanctioned last year, and its cost is 300% above the regional average for a Water Tank."*

## 2. Technology Stack & Tools

To build this within a 2-day hackathon, we need tools that are fast to set up and easy to integrate.

| Component | Tool Chosen | Technical Explanation (What it is & Why we use it) |
| :--- | :--- | :--- |
| **Data Processing** | **Pandas (Python)** | A library that allows us to treat JSON data like a massive Excel spreadsheet in memory. We use it to group, filter, and calculate averages instantly. |
| **Machine Learning (NLP)** | **SentenceTransformers** | A pre-trained Natural Language Processing (NLP) model. It reads human text (project descriptions) and converts it into numbers so the computer understands the *meaning* of the words. We use it to find duplicate projects even if they are worded slightly differently. |
| **Machine Learning (Anomalies)**| **Scikit-Learn (Isolation Forest)** | A library for traditional machine learning. Isolation Forest is an "Unsupervised" algorithm that mathematically isolates data points that look completely different from the rest (outliers). We use it to find weird costs and extreme delays. |
| **Generative AI (Explanations)**| **Google Gemini API / OpenAI API** | A Large Language Model (LLM). We will use it to translate the raw numbers and flags from our ML models into easy-to-read, human-like summaries that explain exactly why a project was flagged. |
| **Database** | **SQLite** | A lightweight database that lives in a single file on the computer. It requires zero setup compared to massive databases like PostgreSQL, making it perfect for a fast hackathon. |
| **Backend API** | **FastAPI (Python)** | A modern, incredibly fast web framework for building APIs. It will act as the bridge between our database and the frontend dashboard. |
| **Frontend UI** | **Next.js / React** | The industry standard for building interactive user interfaces. We will use a charting library like **Recharts** or **Chart.js** to draw the actual graphs. |

## 3. Step-by-Step Execution Plan

### Phase 1: The ML Batch Pipeline (`ai_engine.py`)
This script runs in the background, processes the raw data, applies the AI, and saves the results to the database.

*   **Step 1.1: Data Ingestion & Cleaning.** Load the raw JSON files into Pandas. Convert messy text strings (e.g., `"17-Nov-2025"`) into Datetime objects to mathematically calculate a new **`DAYS_TAKEN`** column (`ACTUAL_END_DATE` minus `SANCTION_DATE`). Handle missing values by flagging projects with no end date as **`IS_STALLED = True`**, which directly feeds the Convergence Board for MPs.
*   **Step 1.2: NLP Sector Tagging (Zero-Shot Classification).** The raw data categorizes everything lazily as "Normal/Others". We will use an NLP Zero-Shot Classifier (or LLM prompt) with a hardcoded "Master List" of official MoSPI sectors (e.g., *Education, Public Health, Drinking Water, Roads, Electricity, Sports*). The AI will read the `WORK_DESCRIPTION` and force the project into the most accurate official bucket. This ensures clean, uniform data for the frontend charts rather than letting the AI invent messy overlapping tags.
*   **Step 1.3: Semantic Clustering (Apples-to-Apples).** Even within a sector like "Education", comparing the cost of a laptop to a massive library creates false positives. We will convert the `WORK_DESCRIPTION` into mathematical vectors using `SentenceTransformers`. We then use **K-Means Clustering** to automatically group projects with identical semantic meaning into unique `CLUSTER_IDs` (e.g., all IT equipment goes to Cluster_A, all building construction goes to Cluster_B).
*   **Step 1.4: Cost Benchmarking Generation.** Group the data by Semantic Cluster and calculate the median `SANCTION_AMOUNT`. Save these benchmarks.
*   **Step 1.5: Run Anomaly Detection.**
    *   *Check 1 (Duplicates):* Calculate **Cosine Similarity** (a math formula that measures how similar two text descriptions are). Flag pairs with >90% similarity.
    *   *Check 2 (Estimate Fraud):* Run the **Isolation Forest** model *within each semantic cluster* to find statistical outliers (e.g., sanctioning ₹50 Lakhs for a water tank that normally costs ₹5 Lakhs).
    *   *Check 3 (Execution Overruns):* Merge the "Works Sanctioned" and "Works Completed" datasets using the unique `WORK_RECOMMENDATION_DTL_ID`. Calculate `(ACTUAL_AMOUNT - SANCTION_AMOUNT) / SANCTION_AMOUNT`. If >10%, flag as a severe Cost Overrun.
*   **Step 1.6: Project Risk Scoring.** Combine the anomaly checks into a single `RISK_SCORE` (0-100). 
    *   *Duplication Penalty:* Up to 40 points based on Cosine Similarity %.
    *   *Cost Penalty:* Up to 40 points based on Isolation Forest extremity and execution overrun %.
    *   *Delay Penalty:* Up to 20 points based on time past the semantic cluster median.
*   **Step 1.7: LLM Explanation Generation.** For every project with `RISK_SCORE > 75`, send the project details and anomaly reasons to an LLM API. The LLM generates a human-readable `llm_explanation` string.
*   **Step 1.8: Database Export (SQLite Schema).** Save the fully enriched dataset into a table called `analyzed_projects`. The final stored schema includes: 
    *   `project_id`, `constituency`, `ida_name`, `description`, `sanction_amt`, `actual_amt` (The raw passthroughs)
    *   `days_taken`, `is_stalled`, `nlp_sector`, `cluster_id` (The engineered features)
    *   `is_duplicate`, `is_estimate_fraud`, `is_execution_overrun`, `risk_score` (The ML outputs)
    *   `llm_explanation` (The AI text)

### Phase 2: The Backend API & Transformations (`main.py`)
FastAPI acts as the aggregation engine. It does not run ML; it runs blazing-fast SQL queries on the SQLite database to format data perfectly for the React frontend charts.

*   **Endpoint A (`/api/oversight/constituencies`):** Calculates the Constituency Risk Index (CRI). It groups the database by `CONSTITUENCY` and applies the formula: `CRI = (0.3 * FAR) + (0.5 * FIR) + (0.2 * SI)`. Returns a sorted JSON array.
*   **Endpoint B (`/api/oversight/sectors`):** Groups the database by `nlp_sector`, counting the ratio of high-risk projects. Returns JSON formatted for Recharts: `[{"name": "Roads", "value": 45}]`.
*   **Endpoint C (`/api/projects/live-feed`):** Queries `SELECT * FROM analyzed_projects WHERE risk_score > 75 ORDER BY risk_score DESC`. Returns the raw high-risk projects, including the pre-generated `llm_explanation`, for instant modal popups.
*   **Endpoint D (`/api/mp-planner/stalled`):** Returns projects where `is_stalled = True` for the Convergence Board.

### Phase 3: The Frontend Dashboard
This is the visual layer.

*   **Component 1:** The Navigation Bar containing the **Mode Toggle** (MP Planner vs. Oversight).
*   **Component 2:** The Charting Grid. We will map the JSON responses from our API endpoints directly into beautiful Recharts components (Pie charts for Sector Vulnerability, Bar charts for Constitutency Rankings).
*   **Component 3:** The Data Tables. For the Agency Leaderboard and the specific list of fraudulent projects.

## 4. The "Guaranteed Demo" Strategy
Real data is unpredictable. To ensure a flawless pitch, we will manually inject 3 specific records into the raw data before running `ai_engine.py`:
1.  **A Duplicate:** Two identical road projects requested by different MPs in the same district.
2.  **A Cost Anomaly:** A "Public Toilet" sanctioned for an absurd ₹50 Crore.
3.  **A Time Anomaly:** A project whose `ACTUAL_END_DATE` is 8 years after its `SANCTION_DATE`.

The AI will catch these 100%. During the live demo, we will point directly to these three projects on the dashboard to prove the ML works perfectly.
